# 仕様書（プロジェクト全体で 1 つ。機能ごとに節を足して育てる）

今のサイトの全体像・規約は `CLAUDE.md` にある。この仕様書には、ハーネスで足していく**機能**を書く。

## 書き方の決まり

- 1 機能 = 1 節（`## <機能の名前>`）。単位はページではなく「ユーザーができること」。
- 節には次を書く：
  - **状態**：下書き / レビュー中 / 承認済み（日付）
  - **目的**：だれが・何のために
  - **できること（受け入れ条件）**：必須 / できれば に分ける。ブラウザ操作か HTTP の応答で機械的に確かめられる文にする
  - **影響範囲**：手が入るページ・共通部品・導線・テスト・privacy・CLAUDE.md
  - **AI が決めたこと**：慣習で埋めたこと（理由つき）
  - **質問リスト**：人にしか決められないこと（答えが出たら答えを書いて残す）
  - **最終レビューで見ること**：主観的なこと（見た目の好みなど）
- 承認済みの節を書き換えるときは、もう一度要件定義ループを回す（状態を「レビュー中」に戻す）。

## ガチャで狙いが手に入るまでの回数と金額を計算する

- **状態**：承認済み（2026-11-22。spec-reviewer のレビュー 2 回を反映）
- **目的**：ソーシャルゲームのガチャを引く人が、確率・すり抜け・天井を入れて、狙いの 1 体が手に入るまでに「平均で何回・いくらかかるか」「運が悪いとどこまでかかるか」「この予算で手に入る確率」を知る。課金する前に、予算の目安を立てられる
- **範囲**：新しいツール「ガチャ天井計算機」（`/tools/gacha`）。狙い 1 体ぶんだけを計算する（2 体以上は注意書きで案内する）。実在のゲームの設定（プリセット）は入れない
- **出し方**：`develop` から切った `feature/gacha-calculator`。PR は `develop` 向け（サイトの作り直しとは別に、今の見た目のまま出す）

### 計算のしかた（決まった値）

1 回引くごとに、次の状態の確率の表を進める（`lib/gacha.ts`。モンテカルロではなく正確に出す）。

- **c**：前に最高レアが当たってから引いた回数（はじめは c₀）。天井 N がないときは持たない
- **s**：いま続いているすり抜けの回数（はじめは s₀）。k が「なし」のときは持たない（状態の数は最大 N ×（k+1））
- **小数の欄（p・q・d・石の数・値段）は 1000 倍した整数で持つ**（小数第 3 位まで。例 p=0.6 → 600）。100% の判定・N'・予算の回数は整数で計算し、確率に直すのは表を進めるときだけ
- **j 回目（j = c+1）に最高レアが当たる確率**：N があり j ≥ N なら 1。そうでなく、ソフト天井（S・d）があり j ≥ S なら `p + d × (j − S + 1)`（%。S 回目は p+d）。それ以外は p。**1000 倍の整数で 100000 以上なら 1** にする（小数の誤差で 0.9999… にしないため）
- **当たったとき**：k があり s ≥ k なら狙い。そうでなければ、確率 `1 − q` で狙い、確率 q ですり抜け（c は 0 に、s は 1 増える）
- **外れたとき**：c が 1 増える
- **狙いが確定するまであと M 回**（交換・期間の天井）：M 回目まで狙いが出なければ M 回目で手に入る（T = `min(自然に出た回数, M)`）
- **結果**：狙いが手に入る回数 T の分布から、平均・50%・90%・99%（T 以下で手に入る確率が 50%・90%・99% 以上になる最も小さい回数。比べるときは 10⁻¹² の誤差を許す）・最大
- **最大**は分布からではなく入力の形から出す：
  - 1 回目のサイクルの上限 `U = N'`（`N'` は「確率が 1 になる最も小さい j」：N・ソフト天井で 100% に届く `S + ⌈(100 − p) / d⌉ − 1`・p=100 なら 1 のうち最も小さいもの。どれもなければ上限なし）
  - 最初の当たりまでは `max(1, N' − c₀)` 回、すり抜けで続く当たりはそれぞれ `N'` 回まで
  - q=0 なら `max(1, N' − c₀)`。k があれば `max(1, N' − c₀) + N' × (k − s₀)`。k が「なし」で q>0 なら上限なし
  - M があれば、上の値（上限なしを含む）と M の小さいほう
- **打ち切り**：残りの確率が 10⁻¹² 未満になるか、最大の回数に着いたら止める。その前に、**進めた回数が 100 万を超えるか、「進めた回数 ×（N または 1）×（k+1 または 1）」が 5,000 万を超えたら、計算しない**（`too-many`。状態の数は確率が 0 かどうかに関係なく、この式で数える）
- **戻り値**：`{ kind: "ok", mean: number, p50: number, p90: number, p99: number, max: number | null, cdf: number[] }`（`cdf[t]` = t 回までに手に入る確率。長さは止めた回数 + 1。`max: null` は上限なし）または `{ kind: "too-many" }`
- **cdf の外の回数**：t が `cdf` の長さ以上なら最後の値を使う。ただし最大があり t ≥ 最大なら 1
- **計算は Web Worker で**行う（`lib/gacha-worker.ts`。正規表現チェックの `regex-worker.ts` と同じ作り）。計算中に入力が変わったら、Worker を止めて新しい入力で計算し直す。要求ごとに番号を付け、古い番号の返事は捨てる。入力のあと 150ms 待ってから計算を始めてよい（デバウンス）。Worker を作れない・落ちたときは、結果の場所に「計算できませんでした。ページを読み込み直してください。」を出す

**入力**（すべて `type="text"`。小数の欄は `inputmode="decimal"`、整数の欄は `numeric`。前後の空白は無視し、全角の数字・ピリオドは半角に直して受ける。それ以外で `^\d+(\.\d{1,3})?$`（小数第 3 位まで。整数の欄は `^\d+$`）に合わないものは不正。`,`・`1e3`・負の数も不正。すべての欄に `autocomplete="off"`。**ラベルは下の表の「ラベル」の文字ちょうど**（単位はラベルの外の `input-group-text`））

| ラベル | 単位 | 範囲 | 空欄 | 最初の値 |
|---|---|---|---|---|
| 最高レアの確率 | % | 0.01〜100 | 不正（必須） | 1 |
| すり抜けの確率 | % | 0〜99 | 0 | 50 |
| すり抜けが続いたら確定 | — | 選択：なし／1 回／2 回／3 回／4 回／5 回 | — | 1 回 |
| いま続いているすり抜け | — | 選択：0 回〜k 回（k 回は「k 回（次は確定）」）。k が「なし」のときは隠し、0 とみなす。k を下げて s₀ が k を超えたら k にする | — | 0 回 |
| 天井（最高レアが必ず出る回数） | 回 | 1〜1000 の整数 | 天井なし | 100 |
| 今のカウント（前の最高レアから引いた回数） | 回 | 0〜N−1 の整数 | 0 | 空欄 |
| ソフト天井の開始 | 回目 | 2〜N−1 の整数 | ソフト天井なし | 空欄 |
| ソフト天井で 1 回ごとに上がる確率 | % | 0.01〜100 | ソフト天井なし | 空欄 |
| 狙いが確定するまであと何回 | 回 | 1〜10000 の整数 | なし | 空欄 |
| 1 回に使う石の数 | 個 | 0.01〜10000 | 不正（必須） | 100 |
| 石 1 個の値段 | 円 | 0.01〜10000 | 不正（必須） | 1 |
| 持っている石 | 個 | 0〜100000000 の整数 | 0 | 空欄 |
| 予算 | 円 | 1〜100000000 の整数 | 予算の行を出さない | 空欄 |

- c₀・S・d は N が空欄（または不正）のときは隠し、確かめず計算にも使わない（値は残す）。S と d は両方入れるか両方空欄
- 記号（p・q・k・s₀・N・c₀・S・d・M）は表の順の欄を指す（この仕様書の中だけの呼び名）。欄の並びはこの表の順。すり抜け（q・k・s₀）と天井（N・c₀・S・d・M）と石・お金（石の数・値段・持っている石・予算）を、それぞれ `<fieldset>`＋`<legend>` でまとめる

**エラーの文**（その欄に `aria-invalid="true"` と、`aria-describedby` でつないだ文を付ける。入力のたびに確かめる。{最小}〜{最大} は 3 桁区切り。必須の欄の空欄は不正にしない（エラーの文は付けず、結果の場所の文で知らせる））

| 場合 | 文 |
|---|---|
| 小数の欄の範囲の外・不正 | 「{最小}〜{最大} の数（小数第 3 位まで）を入れてください」 |
| 整数の欄の範囲の外・不正 | 「{最小}〜{最大} の整数を入れてください」（c₀ は「0〜{N−1} の…」、S は「2〜{N−1} の…」。N を変えて範囲の外になったら c₀・S の側に付ける） |
| S と d の片方だけ | 空いているほうに「ソフト天井の開始と上がる確率は、両方入れてください」 |

**確かめる値**（p・q・d は %。平均の（ ）は小数第 4 位までの真の値）

| 例 | 入力 | 平均 | 50% | 90% | 99% | 最大 |
|---|---|---|---|---|---|---|
| A | p=1 | 100.0（100.0000） | 69 | 230 | 459 | 上限なし |
| B | p=0.6・N=90 | 69.7（69.6998） | 90 | 90 | 90 | 90 |
| C | p=1・M=100 | 63.4（63.3968） | 69 | 100 | 100 | 100 |
| D | p=0.6・N=90・S=74・d=6 | 62.3（62.2973） | 76 | 80 | 83 | 90 |
| E | D ＋ q=50・k=1 | 93.4（93.4460） | 80 | 155 | 161 | 180 |
| F | E ＋ s₀=1 | 62.3（62.2973） | 76 | 80 | 83 | 90 |
| G | E ＋ c₀=50 | 56.8（56.8041） | 32 | 107 | 112 | 130 |
| H | p=1・q=50 | 200.0（200.0000） | 139 | 460 | 919 | 上限なし |
| I | p=100・q=50・k=1 | 1.5（1.5000） | 1 | 2 | 2 | 2 |
| J（最初の値） | p=1・q=50・k=1・N=100 | 95.1（95.0951） | 100 | 180 | 200 | 200 |
| K | p=0.01・q=99 | `too-many` | | | | |
| L | p=0.01・q=99・N=1000 | `too-many` | | | | |

**数の書き方**：`Intl.NumberFormat("ja-JP")` で 3 桁区切り。平均の回数は小数第 1 位まで必ず出す（`toFixed` は使わない）。ほかの回数・石・金額は整数（石と金額は `Math.round`）

- **石** = 回数 × 1 回の石の数
- **金額** = max(0, 回数 × 1 回の石の数 − 持っている石) × 値段 を計算してから、最後に 1 回だけ `Math.round`（平均の行は小数の回数のまま掛ける）
- **最大が上限なし**の行は、回数に「上限なし」、石と金額に「—」
- **予算で手に入る確率**：引ける回数 `n = ⌊(⌊予算 ÷ 値段⌋ + 持っている石) ÷ 1 回の石の数⌋`（1000 倍の整数で計算）、確率は `cdf[n]` を % にして小数第 1 位で**切り捨て**。最大があり n ≥ 最大なら「100%」、それ以外は 99.9% を上限にする。文は「{予算} 円で {n} 回引けます。狙いが手に入る確率は {x}% です。」（予算と n は 3 桁区切り）。n=0 なら「{予算} 円では 1 回も引けません。」
- **グラフ**：横軸は 0〜x_end 回（x_end = 最大があればその回数、なければ 99% の回数）。点は ⌈x_end ÷ 200⌉ 回ごとに取り、(0, 0) と x_end の点を必ず入れる（201 個以下）。y は上の「cdf の外の回数」の決まりで出す。`aria-label` の y は予算と同じ書き方（切り捨て・100% は最大に届くときだけ）

### AI が決めたこと

- **見た目は今の `/tools` と同じ（`layouts.common`・Bootstrap のフォーム）**：道具屋の世界はまだ作り直していないため
- **天井を 2 つに分ける**：「天井 N」（最高レアが必ず出る・当たるとリセット・カウントを持ち越す）と「狙いが確定するまであと M 回」（交換型・期間ごとの天井。途中まで引いた人は残りの回数を入れる＝ユーザーの答え）。両方あるゲームも入れられる
- **ソフト天井は天井 N を入れたときだけ**：計算する状態の数を N ×（k+1）までに抑えるため
- **すり抜けの確定は「k 回続いたら次は確定」**、今の状態は「いま続いているすり抜けの回数」（k=1 なら「次は確定か」と同じ）
- **ピックアップの確率しか書いていないゲーム**のために、すり抜けの欄の説明に「すり抜け = 1 − ピックアップの確率 ÷ 最高レアの確率」を書く。**10 連の割引**は入れず、1 回あたりの石の数に直してもらう（説明に書く）
- **運の幅は 50%・90%・99% と最大**
- **入力は `type="text"`**：`type="number"` は不正な文字が空の値になり、空欄（天井なし）と区別できないため
- **小数は第 3 位まで・1000 倍の整数で計算**：小数の誤差で、ソフト天井が 100% に届く回数や予算で引ける回数が 1 ずれないため（0.005% のような確率にも使える）
- **天井が大きく（1000 回など）、すり抜けの確定も交換もない入力**は「計算できません」になることがある（重さの上限のため。実在のゲームではまずない）
- **最初から Web Worker**：天井 1000 回などの重い入力で画面が固まるため。上限（100 万回・状態の合計 5,000 万）を超えたら計算しない
- **最大は入力の形から出す**：確率の打ち切りや小数の誤差で、天井の回数がずれないため
- **金額の上限**：石の数・値段を 10000 までにして、回数 × 石 × 値段が `Number.MAX_SAFE_INTEGER` を超えないようにする
- **予算の確率は切り捨て**：「99.95%」を「100.0%」と見せないため。100% は最大に届くときだけ
- **持っている石は金額からだけ引く**（石の列は「必要な石の合計」のまま）
- **スマホでも表の 3 列を全部出す**
- **`<noscript>` を付ける**：計算はすべて JS で行うため（今のツールには前例がない）
- **`e2e/pages.ts`** には `/tools/gacha` だけを足す（ほかのページの漏れは別の作業）
- **扱うデータ**：入力はブラウザの中だけで、保存しない（ユーザーの答え）。privacy は一覧に名前を足すだけ
