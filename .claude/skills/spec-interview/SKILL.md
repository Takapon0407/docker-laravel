# 要件定義ループ

ハーネスの全体像は `harness/README.md`。このスキルは**仕様書（`harness/spec.md`）を書くところまで**。コードは書かない。

## 手順

1. **要望を受け取る**：ユーザーの箇条書きメモ（引数か直前の発言）。なければ「何ができるようになればよいか」を 1 つ聞く。
2. **現状を読む**：`CLAUDE.md`・`harness/spec.md`・関係するコード（ルート・ビュー・`config/`・`resources/ts/`）を読む。
3. **影響範囲を洗い出す**：手が入るページ・共通部品（ヘッダー・フッター・`config/tools.php` の一覧など）・追加すべき導線・`privacy.blade.php`（扱うデータが変わるなら）・`CLAUDE.md` の記述・テスト（`tests/Feature`・`e2e/pages.ts`）を列挙する。単位はページではなく**機能（ユーザーができること）**。
4. **下書きを書く**：`harness/spec.md` に機能の節を足す（書き方は spec.md の冒頭の決まり）。受け入れ条件は、ブラウザ操作や HTTP の応答で**機械的に確かめられる文**にする。「おしゃれに」などの主観は「最終レビューで見ること」に分ける。
5. **レビューを受ける**：`spec-reviewer` エージェント（別のコンテキスト・書き込みなし）に、追加した節とコードの場所を渡してレビューさせる。404・meta/OGP・レスポンシブ（PC 幅とスマホ幅）・a11y（キーボード・ラベル・読み上げ）・表示速度・CSP・プライバシーポリシー・空や長すぎる入力などの抜けも指摘させる。
6. **埋める／聞く**：
   - このサイトの既存の慣習（CLAUDE.md・似たツールの作り）で決まることは自分で埋め、spec.md の「AI が決めたこと」に理由と一緒に書く。
   - **人にしか決められないこと**（見せ方の好み・載せる言葉・優先度・範囲）は「質問リスト」に書き、AskUserQuestion でまとめて聞く（1 回 4 問まで）。
7. 答えを反映し、5〜6 を繰り返す。**レビューの往復は 3 回まで**。超えたら残った論点を一覧にしてユーザーに判断を仰ぐ。

## 停止条件

- 質問リストの未解決が 0 件、かつユーザーが spec.md の節を**承認した**（「OK」「承認」など、はっきりした言葉）。
- 承認されたら節の状態を「承認済み（日付）」にし、`/spec-to-features` で features.json に変換することを伝えて終える。自分で実装に進まない。
